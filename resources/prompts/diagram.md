# Инструкция для ИИ: диаграммы `<diagram>`

Эта инструкция дополняет инструкцию профиля ГОСТ и применяется вместе с ней.
Все правила профиля в отношении рисунков (подпись, метка, ссылки в тексте,
размещение) действуют и для диаграмм; здесь описано только то, что относится к
блоку `<diagram>`.

Правила обозначены так же, как в инструкции профиля: **ОБЯЗАТЕЛЬНО**,
**ЗАПРЕЩЕНО**, **РЕКОМЕНДУЕТСЯ**.

---

## 1. Что происходит с блоком `<diagram>`

До передачи документа в pandoc программа находит каждый блок `<diagram>`,
выполняет код из него, сохраняет результат в PNG-файл и **заменяет весь блок
обычной Markdown-картинкой**:

```md
<diagram type="matplotlib" label="fig:loss-curve" caption="Функция потерь при обучении" width="80%">
plt.plot([1.0, 0.6, 0.4, 0.3])
plt.xlabel("Эпоха")
plt.ylabel("Потери")
</diagram>
```

превращается в

```md
![Функция потерь при обучении](diagram_<хеш>.png){#fig:loss-curve width="80%"}
```

Дальше это обычный рисунок: к нему применяются все правила инструкции профиля
ГОСТ. Программа сама добавит «Рисунок N —» к подписи и номер в ссылках.

Следствия:

- Блок `<diagram>` — единственный допустимый способ вставить рисунок, для
  которого у пользователя нет готового файла изображения. Запрет на
  выдуманные имена файлов из инструкции профиля к нему не относится:
  файл создаёт программа.
- Если код блока завершился ошибкой, блок **удаляется из документа целиком**,
  а ошибка записывается в журнал. Рисунка в документе не будет, а ссылки на
  его метку станут неработающими. Поэтому код должен выполняться без ошибок.

## 2. Размещение блока

- **ОБЯЗАТЕЛЬНО:** блок стоит отдельным абзацем — пустая строка до
  открывающего тега и после закрывающего. Иначе картинка окажется внутри
  абзаца текста и не станет пронумерованным рисунком.
- **ОБЯЗАТЕЛЬНО:** теги `<diagram ...>` и `</diagram>` пишутся без отступа, с
  начала строки.
- **ЗАПРЕЩЕНО:** вкладывать блоки `<diagram>` друг в друга.
- **ЗАПРЕЩЕНО:** писать строку `</diagram>` внутри кода (в том числе в
  строковых литералах и комментариях) — она закроет блок.
- Блоки внутри огороженного кода (` ``` `), инлайн-кода и HTML-комментариев
  не выполняются и остаются в тексте как есть. Так можно показать пример
  синтаксиса, но не получить рисунок.

## 3. Атрибуты тега

```md
<diagram type="matplotlib" label="fig:имя" caption="Название рисунка" width="80%" dpi="200">
```

| Атрибут | Обязательность | Значение |
|---|---|---|
| `type` | обязательный | `matplotlib` — единственный поддерживаемый тип |
| `label` | обязательный по ГОСТ | метка рисунка `fig:имя` по правилам меток профиля |
| `caption` | обязательный по ГОСТ | подпись: только название рисунка, по правилам подписей профиля |
| `width` | необязательный | ширина: число с единицей `%`, `cm`, `mm`, `in`, `px`, `pt`, `em`, например `80%` или `14cm` |
| `height` | необязательный | высота, в том же формате |
| `dpi` | необязательный | разрешение PNG, целое число от 1 до 1200; по умолчанию 150 |

- **ОБЯЗАТЕЛЬНО:** значение каждого атрибута заключается в кавычки, двойные
  или одинарные. Атрибут без кавычек (`type=matplotlib`) не распознаётся; без
  `type` блок удаляется.
- **ОБЯЗАТЕЛЬНО:** у каждой диаграммы есть `label` и `caption`. Без `label`
  рисунок не нумеруется и на него нельзя сослаться; без `caption` у рисунка
  нет подписи. Программа выполнит такой блок, но рисунок не будет
  соответствовать ГОСТ.
- Если подпись содержит двойную кавычку, заключите значение в одинарные
  кавычки или запишите кавычку как `&quot;`. Последовательности `&amp;`,
  `&lt;`, `&gt;` раскрываются в `&`, `<`, `>`.
- В подписи допускается инлайн-формула в `$...$`. Квадратные скобки вне
  формул **РЕКОМЕНДУЕТСЯ** не использовать.
- **РЕКОМЕНДУЕТСЯ:** указывать `width` (обычно `70%`–`100%`), чтобы рисунок
  не выходил за поля страницы, и `dpi="200"` или выше для печатного документа.
- Не указывайте `width` и `height` одновременно, если не нужно намеренно
  изменить пропорции рисунка.

## 4. Код диаграммы

Тело блока — код на Python, который выполняется в отдельном процессе.

- Переменная `plt` (`matplotlib.pyplot`) уже доступна, импортировать её не
  нужно. Другие библиотеки импортируются явно; гарантированно установлены
  `numpy`, `scipy` и `pandas`.
- **ОБЯЗАТЕЛЬНО:** код пишется без общего отступа — первая строка кода
  начинается с начала строки. Код с отступом всех строк завершается
  `IndentationError`.
- **ОБЯЗАТЕЛЬНО:** код самодостаточен. Каждый блок выполняется в новом
  процессе: переменные, функции и импорты из других блоков недоступны.
  Данные задаются прямо в коде.
- **ОБЯЗАТЕЛЬНО:** в PNG сохраняется только **текущая** фигура в момент
  окончания кода. Создавайте ровно одну фигуру (`plt.figure(...)` или
  `fig, ax = plt.subplots(...)`). Для нескольких графиков на одном рисунке
  используйте `plt.subplots(nrows, ncols)`; для отдельных рисунков —
  отдельные блоки `<diagram>`.
- **ЗАПРЕЩЕНО:** вызывать `plt.close()` в конце кода — фигура будет закрыта
  до сохранения, и блок завершится ошибкой «ничего не нарисовал».
- **ЗАПРЕЩЕНО:** вызывать `plt.savefig(...)` — изображение сохраняет
  программа; такой вызов только создаёт посторонний файл.
- **ЗАПРЕЩЕНО:** читать или записывать файлы, обращаться к сети, запрашивать
  ввод (`input()`), запускать бесконечные или долгие вычисления.
  Выполнение прерывается через 30 секунд, и блок удаляется.
- `plt.show()` и `print()` допускаются, но не влияют на результат.
- На фигуре должно быть что-то нарисовано (график, текст или изображение);
  пустая фигура считается ошибкой.

## 5. Оформление графика

- **ЗАПРЕЩЕНО:** дублировать подпись рисунка через `plt.title(...)` или
  `fig.suptitle(...)`. Название рисунка по ГОСТ — в подписи под рисунком,
  её формирует программа из `caption`. Заголовки отдельных осей в
  `plt.subplots` допускаются, если они различают части рисунка.
- **ОБЯЗАТЕЛЬНО:** оси подписываются (`xlabel`, `ylabel`) с указанием
  величины и единицы измерения через запятую, например
  `"Время, с"`. Текст на графике пишется на языке документа.
- **РЕКОМЕНДУЕТСЯ:** задавать размер фигуры явно, например
  `figsize=(6.5, 4)` (дюймы), чтобы шрифты на графике соответствовали
  размеру текста документа при `width` около `80%`.
- **РЕКОМЕНДУЕТСЯ:** использовать стандартный шрифт matplotlib без
  переопределения — он поддерживает кириллицу. Указание шрифта, которого
  нет в системе, приводит к замене символов.
- **РЕКОМЕНДУЕТСЯ:** различать линии не только цветом, но и типом линии или
  маркерами, так как документ может печататься в чёрно-белом виде. При
  нескольких сериях данных добавляйте легенду (`plt.legend()`).
- Данные на графике должны соответствовать тексту документа. Если у
  пользователя нет реальных данных, не придумывайте их для иллюстрации
  результатов: используйте диаграммы для схем, функций и данных, которые
  пользователь предоставил или которые следуют из текста.

## 6. Пример

```md
Зависимость точности модели от числа эпох обучения приведена на
рисунке [-@fig:accuracy-epochs].

<diagram type="matplotlib" label="fig:accuracy-epochs" caption="Зависимость точности модели от числа эпох" width="80%" dpi="200">
epochs = [1, 2, 3, 4, 5, 6]
train = [0.62, 0.74, 0.81, 0.86, 0.89, 0.91]
test = [0.60, 0.70, 0.76, 0.79, 0.80, 0.80]

fig, ax = plt.subplots(figsize=(6.5, 4))
ax.plot(epochs, train, marker="o", linestyle="-", label="Обучающая выборка")
ax.plot(epochs, test, marker="s", linestyle="--", label="Тестовая выборка")
ax.set_xlabel("Эпоха")
ax.set_ylabel("Точность, доля")
ax.grid(True, alpha=0.3)
ax.legend()
</diagram>

После шестой эпохи точность на тестовой выборке перестаёт расти.
```
