# Инструкция для ИИ: подготовка Markdown-документа по ГОСТ 7.32-2017

Профиль программы: `GOST_7.32-2017`. Версия инструкции: 1.1.

Эта инструкция — полное и единственное руководство по созданию исходных файлов, из которых программа-конвертер собирает документ Word (DOCX), оформленный по ГОСТ 7.32-2017 «Отчёт о научно-исследовательской работе. Структура и правила оформления». Прочитай её целиком до того, как напишешь первую строку. Каждое правило здесь появилось не случайно: за ним стоит конкретное поведение программы, проверенное на реальной сборке. Если правило кажется странным, ищи рядом объяснение «почему» — оно всегда есть.

---

## Часть 0. Как читать эту инструкцию

1. Правила делятся на три вида:
   - **ОБЯЗАТЕЛЬНО** — нарушение ломает документ или делает его не соответствующим ГОСТ;
   - **ЗАПРЕЩЕНО** — конструкция, которая выглядит безобидно, но программа превращает её в ошибку; рядом всегда указано, что писать вместо неё;
   - **РЕКОМЕНДУЕТСЯ** — улучшает качество, но не критично.
2. Если два правила противоречат друг другу (такого не должно быть, но вдруг), приоритет такой: техническое правило программы > требование ГОСТ > пожелание пользователя по форме > стилистическая рекомендация. Пожелание пользователя по **содержанию** выполняется всегда.
3. Если пользователь прямо просит нарушить техническое правило (например, «пронумеруй рисунки вручную»), выполни просьбу по смыслу правильным способом и коротко объясни ему в сообщении (не в документе), что программа сделает это сама.
4. Примеры даны в блоках кода. Строки, помеченные `НЕПРАВИЛЬНО`, не копируются никогда. Строки ` ```md `, ` ```bib ` и закрывающие ` ``` `, обрамляющие примеры, — это рамка примера в инструкции, а не часть документа.

## Часть 1. Ментальная модель: что происходит с твоим текстом

Ты не верстаешь документ. Ты пишешь **разметку смысла**, а всю вёрстку делает программа. Чем точнее ты это понимаешь, тем меньше ошибок.

### 1.1 Конвейер обработки

Программа получает от пользователя твой файл `.md`, твой файл `.bib`, шаблон титульного листа и профиль ГОСТ. Дальше она по шагам:

1. Читает `.md` (ожидается UTF-8).
2. **Сама нумерует заголовки** первого, второго и третьего уровней: `1`, `1.1`, `1.1.1`. Номер вписывается в начало текста заголовка.
3. Ищет блок списка литературы `::: {#refs}`; если его нет — дописывает его в самый конец документа (это плохо, см. часть 3.10).
4. Запускает Pandoc со следующими механизмами:
   - **pandoc-crossref** — сам нумерует рисунки, таблицы и формулы и подставляет номера вместо ссылок вида `[-@fig:метка]`;
   - **citeproc** со стилем ГОСТ Р 7.0.5-2008 (числовой) — превращает `[@ключ]` в `[1]` и формирует список литературы из `.bib`;
   - **фильтр профиля** — назначает стили таблицам и рисункам, превращает `---` в разрыв страницы и превращает **каждый одиночный перевод строки внутри абзаца в принудительный разрыв строки**;
   - **шаблон стилей** — шрифт Times New Roman 14 пт, полуторный интервал, абзацный отступ, поля, нумерация страниц, стили подписей.
5. Генерирует **содержание** автоматически (заголовки уровней 1–3).
6. Приклеивает **титульный лист** из отдельного шаблона пользователя.

### 1.2 Разделение ответственности

| Делает программа (ты НЕ делаешь) | Делаешь ты (программа НЕ сделает) |
|---|---|
| Номера разделов, подразделов, пунктов | Правильный уровень каждого заголовка |
| Номера рисунков, таблиц, формул | Метку `{#fig:...}` у каждого рисунка, `{#tbl:...}` у каждой таблицы, `{#eq:...}` у каждой формулы |
| Слова «Рисунок», «Таблица» и тире в подписи | Текст подписи (только название) |
| Номера в ссылках на рисунки, таблицы, формулы, разделы | Ссылку `[-@fig:...]` в тексте до объекта и правильное слово перед ней |
| Номера источников `[1]`, `[2]` | Ссылку `[@ключ]` на каждый источник |
| Оформление списка литературы по ГОСТ Р 7.0.5 | Полные и правдивые данные в `.bib` |
| Содержание | Ничего: содержание не пишется |
| Титульный лист | Ничего: титульный лист не пишется |
| Шрифт, интервалы, поля, отступы, выравнивание | Ничего: оформление не пишется |
| Начало каждого раздела первого уровня с новой страницы | Ничего |
| Номера страниц | Ничего |
| — | Структуру документа по ГОСТ (порядок элементов) |
| — | Реферат, включая подсчёт рисунков, таблиц, источников, приложений и оценку страниц |
| — | Язык: научный стиль, типографику, единицы величин |
| — | Приложения: буквенные обозначения и атрибут `{label="буква"}` в заголовке |

Главная мысль этой таблицы: **всё, что можно посчитать, программа считает сама. Если ты тоже посчитаешь и впишешь номер — получится двойной номер или рассинхронизация.**

## Часть 2. Формат выдачи

### 2.1 Что ты выдаёшь

ОБЯЗАТЕЛЬНО выдать **ровно два файла**:

1. `document.md` — текст документа (имя может быть другим, если пользователь просит, но расширение `.md`).
2. `references.bib` — библиография в формате BibLaTeX.

Файл `.bib` обязателен всегда, когда в документе есть список использованных источников, а по ГОСТ 7.32 он есть практически всегда. Документ, в котором источники перечислены вручную текстом, считается ошибочным (см. часть 6).

### 2.2 Как передавать файлы в чате

Если ты можешь создавать файлы напрямую — создай два файла, обёртки не нужны.

Если не можешь, выдай каждый файл **отдельным** блоком кода строго по образцу: строка с именем файла, пустая строка, блок кода. Блок открывается **тремя** обратными апострофами с меткой языка — `md` для документа, `bib` для библиографии — и закрывается тремя обратными апострофами на отдельной строке. Выдача выглядит ровно так:

Файл: document.md

```md
# РЕФЕРАТ {-}

…остальное содержимое document.md…
```

Файл: references.bib

```bib
@book{ivanov2021,
  …остальные записи references.bib…
}
```

**ЗАПРЕЩЕНО**:

- открывать или закрывать блок четырьмя, пятью и более обратными апострофами (` ```` `, ` ````` `);
- вкладывать оба файла в один общий внешний блок (` ```text `, ` ````` ` и т. п.);
- использовать другие метки языка (`markdown`, `bibtex`, `text`) или блок без метки;
- ставить что-либо на одной строке с открывающими или закрывающими апострофами.

Почему: многие чаты и редакторы распознают только стандартную обёртку из трёх апострофов. Нестандартную обёртку они показывают как обычный текст, пользователь копирует её вместе с содержимым, и в Word попадают строки вида «Файл: document.md» и «````markdown», а разметка перестаёт работать. Это проверено на реальных сборках.

Чтобы блок документа не закрылся раньше времени, внутри `document.md` **никогда не используются** строки из трёх обратных апострофов: блоки программного кода в документе пишутся через три тильды `~~~` (см. часть 4.11). Тогда первая же строка ` ``` ` после открытия ` ```md ` — это конец файла, и ничего не разрезается. В `references.bib` обратных апострофов нет вообще.

Строки ` ```md `, ` ```bib ` и закрывающие ` ``` ` — рамка для передачи, а не содержимое: файл `document.md` начинается с первого заголовка, а `references.bib` — с первой записи `@`.

Внутри файлов — только их содержимое: никаких «Вот ваш документ:», пояснений для пользователя, упоминаний о том, что текст написан ИИ. Все пояснения, предупреждения и оценки (например, оценку числа страниц) — **в сообщении вне файлов**.

### 2.3 Общие свойства файла `.md`

- Кодировка UTF-8.
- Файл начинается сразу с первого заголовка. **ЗАПРЕЩЕНО** начинать файл с блока метаданных YAML (`---` … `---`), подробно — в части 4.6.
- Между любыми двумя соседними элементами документа — **ровно одна** пустая строка: не ноль и не две. Что такое элемент и почему это важно — в части 4.5.
- В конце строк нет пробелов; файл заканчивается одним переводом строки.

## Часть 3. Архитектура документа по ГОСТ 7.32-2017

### 3.1 Порядок структурных элементов

ГОСТ 7.32-2017 задаёт следующий порядок. Элементы, помеченные «авто», ты не пишешь.

| № | Элемент | Обязательность | Кто создаёт |
|---|---|---|---|
| 1 | Титульный лист | обязательно | авто (шаблон) |
| 2 | Список исполнителей | для отчёта о НИР, если исполнителей больше одного | ты, только если пользователь дал данные |
| 3 | Реферат | обязательно для отчёта о НИР; для курсовой и ВКР — по умолчанию включай, если пользователь не сказал обратное | ты |
| 4 | Содержание | обязательно | авто |
| 5 | Термины и определения | по необходимости | ты |
| 6 | Перечень сокращений и обозначений | по необходимости | ты |
| 7 | Введение | обязательно | ты |
| 8 | Основная часть (разделы) | обязательно | ты |
| 9 | Заключение | обязательно | ты |
| 10 | Список использованных источников | обязательно | ты (заголовок и блок `{#refs}`) + авто (сам список) |
| 11 | Приложения | по необходимости | ты |

Как решать про необязательные элементы:

- «Термины и определения» включай, если в работе есть специальные термины, которые можно понять неоднозначно (обычно от пяти терминов).
- «Перечень сокращений и обозначений» включай, если в тексте больше трёх нестандартных сокращений или условных обозначений. Общепринятые сокращения («т. е.», «и т. д.», «ГОСТ», «РФ») туда не входят.
- Даже если перечень есть, при первом упоминании в тексте сокращение всё равно расшифровывается.

### 3.2 Точные заголовки структурных элементов

Заголовки структурных элементов пишутся **ПРОПИСНЫМИ** буквами, уровнем `#` и **всегда** с атрибутом `{-}` (он означает «не нумеровать»), кроме приложений: у них атрибут `{label="буква"}`. Формулировки — дословно эти:

```md
# СПИСОК ИСПОЛНИТЕЛЕЙ {-}
# РЕФЕРАТ {-}
# ТЕРМИНЫ И ОПРЕДЕЛЕНИЯ {-}
# ПЕРЕЧЕНЬ СОКРАЩЕНИЙ И ОБОЗНАЧЕНИЙ {-}
# ВВЕДЕНИЕ {-}
# ЗАКЛЮЧЕНИЕ {-}
# СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ {-}
# ПРИЛОЖЕНИЕ А {label="А"}
```

Почему так:

- без `{-}` программа присвоит «Введению» номер 1, настоящая первая глава станет второй, и сдвинется нумерация всех рисунков, таблиц и формул;
- `{label="А"}` сообщает программе букву приложения: заголовок приложения остаётся без номера, а рисунки, таблицы и формулы внутри него получают номера «А.1», «А.2» (подробно в части 5.11);
- ГОСТ требует печатать заголовки структурных элементов прописными; шаблон сам этого не делает, поэтому прописные пишешь ты;
- **СОДЕРЖАНИЕ не пишется никогда** — программа вставляет его сама. Если написать `# СОДЕРЖАНИЕ`, в документе будет два содержания, и ручное не совпадёт с реальными страницами.

### 3.3 Список исполнителей

Включай только если пользователь назвал исполнителей. **ЗАПРЕЩЕНО** придумывать ФИО, должности, учёные степени. Оформляй таблицей без подписи и без метки — это единственная таблица основной части без номера, потому что по смыслу это не таблица, а список:

```md
# СПИСОК ИСПОЛНИТЕЛЕЙ {-}

| Должность, учёная степень | Подпись, дата | Инициалы, фамилия | Вклад |
|---|---|---|---|
| Руководитель НИР, канд. техн. наук, доцент |  | И. И. Иванов | введение, раздел 1, заключение |
| Исполнитель, инженер |  | П. П. Петров | разделы 2, 3 |
```

Пустая ячейка «Подпись, дата» здесь допустима: её заполняют от руки.

### 3.4 Реферат

Реферат — краткая характеристика работы, его читают первым. Он строится из трёх частей строго в таком порядке.

1. **Сведения об объёме** — один абзац по образцу:
   `Отчет 54 с., 12 рис., 6 табл., 25 источн., 3 прил.`
   - первое слово соответствует типу документа: «Отчет», «Курсовая работа», «Выпускная квалификационная работа», «Пояснительная записка»;
   - отсутствующие элементы (например, нет приложений) не упоминаются;
   - сокращения именно такие: `с.`, `рис.`, `табл.`, `источн.`, `прил.`; между числом и сокращением пробел; элементы через запятую; в конце точка.
2. **Ключевые слова** — отдельный абзац: от 5 до 15 слов или словосочетаний **ПРОПИСНЫМИ** буквами, в именительном падеже, через запятую, без точки в конце. Пример: `НЕЙРОННАЯ СЕТЬ, КЛАССИФИКАЦИЯ ИЗОБРАЖЕНИЙ, СВЁРТОЧНЫЙ СЛОЙ, ТОЧНОСТЬ, ОБУЧАЮЩАЯ ВЫБОРКА`.
3. **Текст реферата** — несколько абзацев без подзаголовков, в которых по порядку раскрыто: объект исследования; цель работы; методы проведения работы; полученные результаты и их новизна; основные характеристики (если применимо); степень внедрения; рекомендации по внедрению; область применения; значимость работы; прогноз развития объекта исследования. Неприменимые пункты пропускай, а не заполняй водой. Объём текста — до 850 знаков (примерно 6–9 предложений).

Цифры для строки объёма считаются **после того, как написан весь документ**:

- `рис.` — число рисунков с меткой `{#fig:...}`;
- `табл.` — число таблиц с меткой `{#tbl:...}` (таблица списка исполнителей не считается);
- `источн.` — число **различных** ключей, на которые в тексте есть хотя бы одна ссылка `[@...]` (не число записей в `.bib`!);
- `прил.` — число заголовков `# ПРИЛОЖЕНИЕ ...`;
- `с.` — точного числа страниц ты знать не можешь, поэтому оцени его: одна страница ≈ 1800 знаков текста с пробелами; плюс 1 страница на титульный лист и 1–2 на содержание; плюс примерно половина страницы на каждый рисунок и треть — на каждую таблицу; плюс половина страницы на каждый заголовок первого уровня (каждый начинается с новой страницы, и последняя страница раздела обычно неполная). Округли до целого. **В сообщении пользователю** (не в документе) обязательно напиши, что число страниц оценочное и его нужно сверить в Word.

### 3.5 Термины и определения

Начинается с фиксированной фразы, затем каждый термин — отдельный абзац, в алфавитном порядке:

```md
# ТЕРМИНЫ И ОПРЕДЕЛЕНИЯ {-}

В настоящем отчете о НИР применяют следующие термины с соответствующими определениями.

Валидационная выборка: подмножество данных, используемое для подбора гиперпараметров модели и не участвующее в обучении.

Переобучение: состояние модели, при котором качество на обучающих данных существенно выше, чем на новых данных.
```

Для курсовой или ВКР вместо «отчете о НИР» пиши «работе».

### 3.6 Перечень сокращений и обозначений

```md
# ПЕРЕЧЕНЬ СОКРАЩЕНИЙ И ОБОЗНАЧЕНИЙ {-}

В настоящем отчете о НИР применяют следующие сокращения и обозначения.

БД — база данных

ИНС — искусственная нейронная сеть

СУБД — система управления базами данных
```

Каждое сокращение — отдельный абзац (пустая строка между ними). Порядок алфавитный, сначала кириллица, потом латиница. Точка в конце не ставится.

### 3.7 Введение

Во введении обычными абзацами, без подзаголовков, раскрываются: современное состояние проблемы; актуальность; цель работы; задачи (удобно оформить списком); объект и предмет исследования; методы; научная новизна и практическая значимость (если применимо); краткое описание структуры работы (что рассматривается в каждом разделе). Цель одна, в одном предложении. Задач обычно 3–6, каждая начинается с глагола в неопределённой форме («проанализировать», «разработать», «оценить»). Каждой задаче соответствует раздел или подраздел основной части и вывод в заключении.

Во введении **нет** рисунков, таблиц и нумерованных формул — причина в части 5.11.

### 3.8 Основная часть

- Состоит из разделов уровня `#` (без `{-}`), внутри — подразделы `##` и пункты `###`.
- Обычно 2–4 раздела: аналитический (обзор, постановка задачи), методический или проектный (метод, модель, архитектура), практический (реализация, расчёты, результаты).
- После заголовка раздела, до первого подраздела, — 1–3 вводных абзаца. Заголовок, сразу за которым идёт другой заголовок, — ошибка.
- Если подраздел внутри раздела один, деление не нужно — убери его. То же для пунктов.
- В конце раздела рекомендуется абзац выводов без отдельного заголовка, например начинающийся со слов «Таким образом,».
- Рисунки, таблицы и формулы с номерами размещаются только в основной части и в приложениях.

### 3.9 Заключение

Заключение содержит: краткие выводы по результатам; оценку полноты решения задач (по каждой задаче из введения — что сделано); рекомендации по использованию результатов; оценку эффективности или значимости (если применимо); направления дальнейшей работы. Новые факты, источники, рисунки, таблицы и формулы в заключение не вводятся.

### 3.10 Список использованных источников

Пишется всегда **ровно так** — после заключения и перед первым приложением (или в конце, если приложений нет):

```md
# СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ {-}

::: {#refs}
:::
```

Строки `::: {#refs}` и `:::` отмечают место, куда программа вставит оформленный список. Внутри ничего не пиши. Почему вручную: если блока нет, программа допишет его в самый конец файла — **после приложений и без заголовка**. Это нарушение ГОСТ, которое потом не исправить без ручной правки DOCX.

### 3.11 Приложения

- Обозначаются заглавными буквами русского алфавита по порядку, **кроме** Ё, З, Й, О, Ч, Ъ, Ы, Ь. Допустимая последовательность: А, Б, В, Г, Д, Е, Ж, И, К, Л, М, Н, П, Р, С, Т, У, Ф, Х, Ц, Ш, Щ, Э, Ю, Я.
- На каждое приложение есть ссылка в основной части («приведён в приложении А»). Приложения идут в порядке первых ссылок на них.
- Каждое приложение оформляется так — три обязательных элемента: обозначение, статус, название:

```md
# ПРИЛОЖЕНИЕ А {label="А"}

::: {custom-style="Subtitle"}
(обязательное)

Исходный код модуля обработки данных
:::

Текст приложения.
```

- Статус — одно из трёх слов в скобках: `(обязательное)`, `(рекомендуемое)`, `(справочное)`. Если не знаешь, что выбрать: исходный код, расчёты, протоколы испытаний — `(обязательное)`; дополнительные примеры и иллюстрации — `(справочное)`.
- Блок `::: {custom-style="Subtitle"}` … `:::` — специальная конструкция профиля, она выравнивает статус и название по центру. Используй её **только здесь** и дословно. Других значений `custom-style` не придумывай: их нет в шаблоне, и текст получит случайное оформление.
- В заголовке приложения стоит атрибут `{label="буква"}` с той же буквой, что в тексте заголовка: `# ПРИЛОЖЕНИЕ А {label="А"}`, `# ПРИЛОЖЕНИЕ Б {label="Б"}`.
- Внутри приложения всё оформляется так же, как в основной части: подзаголовки, рисунки, таблицы, формулы и ссылки на них (подробно в части 5.11).

## Часть 4. Базовый синтаксис и его ловушки

### 4.1 Абзац — это одна строка

**ОБЯЗАТЕЛЬНО: один абзац = одна физическая строка в файле, какой бы длинной она ни была.** Абзацы разделяются одной пустой строкой.

Почему: программа превращает каждый одиночный перевод строки внутри абзаца в принудительный разрыв строки. В обычном Markdown перенос строки внутри абзаца ничего не значит, а здесь значит. Если ты по привычке переносишь строки на 80 символах, в Word каждая строка оборвётся посередине, а выравнивание по ширине растянет слова на полстраницы.

```md
НЕПРАВИЛЬНО (абзац разбит на строки — в документе будет «лесенка»):
Метод опорных векторов широко применяется в задачах
классификации благодаря устойчивости к переобучению
и хорошей обобщающей способности.

ПРАВИЛЬНО:
Метод опорных векторов широко применяется в задачах классификации благодаря устойчивости к переобучению и хорошей обобщающей способности.
```

Есть **ровно одно** исключение — пояснение символов после формулы (часть 5.6): там каждый символ должен быть с новой строки, и разрыв строки внутри абзаца — именно то, что нужно.

### 4.2 Заголовки

Синтаксис — только `#`, `##`, `###` в начале строки, затем пробел, затем текст:

```md
# Анализ предметной области

## Обзор существующих решений

### Сравнение по производительности
```

**ЗАПРЕЩЕНО писать номер раздела в заголовке.** Ни `# 1 Анализ`, ни `# 1. Анализ`, ни `# Глава 1. Анализ`, ни `## 2.3 Обзор`.

Понимай механизм, а не просто запрет: программа читает заголовки сверху вниз и сама ставит каждому номер. Если она увидит, что ты уже написал правильный по порядку номер, она его примет. Но если номер хоть немного не совпал с её счётчиком (ты пропустил подраздел, переставил раздел, ошибся на единицу), твоя цифра станет просто частью текста, и программа добавит свою: в документе появится `1.2 2.5 Обзор`. Ты физически не можешь видеть итоговую нумерацию, а программа видит её всегда. Поэтому номер — её зона ответственности. То же относится к словам «Глава», «Раздел», «Часть» в заголовке: в ГОСТ 7.32 их нет вообще.

Ещё правила для заголовков:

- **Уровни идут подряд.** После `#` может идти только `##`, после `##` — только `###`. Пропуск уровня (`#`, затем сразу `###`) программа не нумерует, и пункт останется без номера.
- **Максимум три уровня.** `####` не нумеруется и не попадает в содержание. Если нужна более мелкая детализация — используй список, а не четвёртый уровень.
- **Заголовок не начинается с цифры.** `# 2024 год в отрасли` даст «2 2024 год в отрасли». Переформулируй: `# Состояние отрасли в 2024 году`.
- **Без точки в конце.** Двоеточие, вопросительный и восклицательный знаки в заголовках тоже не используются. Если заголовок из двух предложений, они разделяются точкой, но в конце точки нет — лучше переформулировать в одно.
- **Только простой текст.** В заголовке не бывает выделения (`**`, `*`), ссылок на источники, сносок, формул, кода, гиперссылок. Всё это ломает строку содержания.
- **Первая буква прописная, остальные — по правилам русского языка.** Прописными целиком пишутся только заголовки структурных элементов (часть 3.2).
- Заголовок раздела основной части **никогда не имеет** `{-}`. Атрибут `{-}` — только у структурных элементов из части 3.2.
- Заголовок — короткий, обычно до 10 слов, и точно отражает содержание.
- Ни один заголовок не повторяет другой дословно.

Чтобы на раздел можно было сослаться, добавь ему метку (часть 5.7):

```md
## Обзор существующих решений {#sec:review}
```

### 4.3 Ловушка «строка над чертой»

**ЗАПРЕЩЕНО подчёркивать строку символами `===` или `---`.** В Markdown строка текста, сразу под которой (без пустой строки) идёт `===` или `---`, становится заголовком. Программа такой заголовок тоже нумерует, и вся нумерация после него сдвигается на единицу. Это проверено: абзац «Текст перед линией» с `---` под ним превратился в подраздел «1.1 Текст перед линией», а следующий настоящий подраздел стал 1.2 вместо 1.1.

```md
НЕПРАВИЛЬНО (абзац станет подразделом и сдвинет нумерацию):
Результаты приведены ниже.
---

ПРАВИЛЬНО (если разрыв страницы действительно нужен — пустые строки с обеих сторон):
Результаты приведены ниже.

---

Следующий абзац начнётся с новой страницы.
```

### 4.4 Разрыв страницы

Строка `---`, окружённая пустыми строками, означает «следующий блок начать с новой страницы». Строки `***` и `___` работают так же — поэтому никогда не используй их как «декоративную черту».

- Перед заголовком `#` разрыв **не нужен**: каждый раздел первого уровня и так начинается с новой страницы (программа выбросит лишний `---` перед `#`).
- Внутри разделов используй разрыв только по явной просьбе пользователя или чтобы большая таблица целиком начиналась с новой страницы. По умолчанию — не используй.
- Несколько `---` подряд дают один разрыв, а не несколько пустых страниц.

### 4.5 Пустые строки между элементами

**ОБЯЗАТЕЛЬНО: между любыми двумя соседними элементами — ровно одна пустая строка (то есть два перевода строки подряд). Не ноль и не две.**

Элемент — это не строка файла, а то, что в Word становится одним самостоятельным блоком. Элемент может занимать одну строку, а может несколько(например таблица) — тогда внутри него пустых строк нет, а пустая строка ставится только до и после него целиком:

| Элемент | Строк в файле | Пустые строки внутри элемента |
|---|---|---|
| Заголовок | одна | — |
| Абзац (в том числе ключевые слова реферата, примечание, термин, сокращение) | одна (часть 4.1) | — |
| Список целиком, со всеми пунктами и вложенными уровнями | несколько | нет |
| Строка подписи таблицы `: … {#tbl:…}` | одна | — |
| Таблица целиком: строка заголовков, строка выравнивания, все строки данных | несколько | нет |
| Рисунок | одна | — |
| Выключенная формула с меткой | одна | — |
| Пояснение «где …» | несколько | нет |
| Блок кода от `~~~` до `~~~` | несколько | только те, что есть в самом коде |
| Разрыв страницы `---` | одна | — |
| Определение сноски `[^…]: …` | одна | — |
| Блок `::: {#refs}` и `:::` | две | нет |
| Блок `::: {custom-style="Subtitle"}` … `:::` | пять | ровно одна — между статусом и названием |

Пример правильной последовательности элементов:

```md
# РЕФЕРАТ {-}

Курсовая работа 12 с., 1 рис., 3 табл., 6 источн., 1 прил.

КЛАССИФИКАЦИЯ ТЕКСТОВ, МАШИННОЕ ОБУЧЕНИЕ, F-МЕРА

Объектом исследования являются текстовые обращения пользователей.
```

```md
НЕПРАВИЛЬНО (элементы слиплись — в Word это один абзац с разрывами строк):
# РЕФЕРАТ {-}
Курсовая работа 12 с., 1 рис., 3 табл., 6 источн., 1 прил.
КЛАССИФИКАЦИЯ ТЕКСТОВ, МАШИННОЕ ОБУЧЕНИЕ, F-МЕРА
```

Почему ровно одна:

- **Без пустой строки** соседние абзацы сливаются в один, а перевод строки между ними превращается в принудительный разрыв строки (часть 4.1). Список или таблица без пустой строки перед ними не распознаются и становятся текстом с вертикальными чертами и дефисами. Текст без пустой строки над `---` становится заголовком (часть 4.3).
- **Пустая строка внутри элемента** разрывает его: таблица распадается на две, список — на два списка с разными отступами, пояснение «где» — на отдельные абзацы.
- **Две и больше пустые строки подряд** — шум, по которому сразу видна небрежная генерация. Пустые абзацы, строки из пробелов и `&nbsp;` для «отступа» тоже запрещены: отступы задаёт шаблон.

Отдельно о пробелах: два пробела в конце строки Markdown превращает в разрыв строки, поэтому в конце строк пробелов нет вообще.

### 4.6 Никаких метаданных YAML

**ЗАПРЕЩЕНО** начинать файл с блока

```md
---
title: "..."
author: "..."
---
```

Почему: название из `title` программа печатает отдельной строкой прописными буквами в теле документа, на странице содержания, — это лишний текст, которого нет в ГОСТ. Название, автор, организация, год уже есть в титульном листе, который программа берёт из шаблона. Метаданные не нужны ни для чего.

### 4.7 Списки

Синтаксис: неупорядоченный список — дефис и пробел; упорядоченный — число, **закрывающая скобка** и пробел. Перед списком обязательно пустая строка. Элементы одного списка идут подряд, без пустых строк между ними.

```md
Для решения поставленной цели необходимо решить следующие задачи:

- проанализировать существующие методы распознавания;
- разработать архитектуру модели;
- оценить точность модели на тестовой выборке.
```

```md
Порядок развёртывания включает следующие этапы:

1) установка зависимостей;
2) настройка переменных окружения;
3) запуск миграций базы данных.
```

Правила оформления списков (по ГОСТ):

- Список всегда вводится предложением, которое заканчивается **двоеточием**.
- Элементы начинаются со **строчной** буквы и заканчиваются **точкой с запятой**; последний элемент — **точкой**.
- Если элемент списка состоит из нескольких предложений, все элементы начинаются с прописной буквы и заканчиваются точкой.
- Неупорядоченный список (`-`) — по умолчанию. Упорядоченный (`1)`) — только если важна последовательность или на элементы ссылаются в тексте.
- Каждый элемент — одна строка (правило части 4.1 действует и здесь).
- **ЗАПРЕЩЕНЫ** маркеры `*` и `+` (дефис — единственный), а также буквенные маркеры `а)`, `б)`. Кириллические буквы программа не распознаёт как список: строки слипнутся в один абзац с разрывами строк. Латинские `a)` распознаются, но в русском тексте по ГОСТ латиница в перечислениях недопустима.
- Вложенный список — отступ **четыре пробела**; вложенность не больше двух уровней:

```md
Система состоит из следующих модулей:

- модуль сбора данных, включающий:
    - адаптер базы данных;
    - адаптер внешнего API;
- модуль обработки;
- модуль визуализации.
```

- Не начинай обычный абзац с числа с точкой и пробелом (`1. В первую очередь…`, `2024. Год…`) — Markdown может принять его за упорядоченный список. Переформулируй: «В первую очередь…», «В 2024 году…».
- Список не может быть единственным содержимым подраздела: перед ним вводная фраза, после — по возможности абзац.

### 4.8 Выделение текста

- `*курсив*` — допускается редко: для термина в момент его определения и для латинских названий видов. Не больше нескольких раз на раздел.
- `**полужирный**` — в основном тексте **не используется**. ГОСТ не предусматривает выделения полужирным в тексте; «важные слова жирным», «**Вывод:**», «**Примечание:**» — типичная ошибка ИИ.
- **ЗАПРЕЩЕНЫ**: зачёркивание `~~…~~`, подчёркивание, цвет, HTML-теги (`<b>`, `<u>`, `<br>`, `<span>`, `<div>`, `<center>`), смайлики и эмодзи, декоративные символы (★, ✓, ➤, •).
- Слова прописными буквами для акцента — запрещены. Прописными пишутся только заголовки структурных элементов, ключевые слова реферата и аббревиатуры.

### 4.9 Примечания и сноски

**Примечание** к тексту, рисунку или таблице оформляется абзацем, начинающимся со слова «Примечание» и тире, сразу после того, к чему оно относится:

```md
Примечание — Значения получены при температуре окружающей среды 20 °C.
```

Если примечаний несколько, пиши «Примечания» и затем нумерованный список `1)`, `2)`.

**Сноска** — синтаксис `[^1]` в тексте и определение отдельной строкой ниже (лучше в конце текущего подраздела):

```md
Метод был впервые предложен в 1995 году[^svm].

[^svm]: Здесь и далее имеется в виду формулировка с мягким зазором.
```

Сноски используй редко, только для пояснений. **ЗАПРЕЩЕНО** использовать сноски для библиографических ссылок: для этого есть `[@ключ]`.

### 4.10 Цитаты и гиперссылки

- Прямая цитата — в кавычках «ёлочках» внутри абзаца, сразу со ссылкой на источник: `…отмечает, что «…» [@ivanov2021, с. 45].`
- Блок цитаты `> …` **не используется**: шаблон его не оформляет по ГОСТ.
- Голые адреса сайтов в тексте (`https://…`) и гиперссылки `[текст](https://…)` **не используются**. Сайт — это источник: заведи для него запись `@online` в `.bib` и сошлись `[@ключ]`.

### 4.11 Код и программные тексты

- Имена функций, файлов, команд внутри абзаца — в обратных апострофах: `` `train_model()` ``.
- Блок кода — **три тильды** `~~~` с указанием языка в начале и три тильды в конце, каждая на отдельной строке:

~~~python
def normalize(x):
    return (x - x.mean()) / x.std()
~~~

- **ЗАПРЕЩЕНО** открывать блок кода в документе обратными апострофами ` ``` `. Это стандартный синтаксис, но документ передаётся в чате внутри блока ` ```md ` (часть 2.2), и первая же строка ` ``` ` внутри документа закроет его раньше времени — файл разрежется пополам. Тильды `~~~` программа понимает точно так же, а внешний блок они не закрывают.
- Количество тильд — ровно три, и открывающая, и закрывающая строки.

- В основной части — только короткие фрагменты (до 15–20 строк), поясняющие текст. Полные листинги — в приложение (обычно со статусом «обязательное»).
- Блоки кода **не получают подписей и меток** (`{#lst:...}` не поддерживается этим профилем). Если на фрагмент нужно сослаться, сделай ссылку словами: «фрагмент кода, приведённый ниже».
- Длина строки кода — до 80 символов, иначе строка уйдёт за поле страницы.

### 4.12 Экранирование специальных символов

Некоторые символы в обычном тексте программа воспринимает как разметку. Проверь каждый абзац:

| Что хочешь написать | Что произойдёт без экранирования | Как писать правильно |
|---|---|---|
| `@` перед словом: «пользователь @admin» | ссылка на несуществующий источник, в документе «[admin?]» | `\@admin` или перефразировать; адреса почты `ivan@mail.ru` безопасны |
| `*` как знак умножения: `2*3` | курсив до следующей звёздочки | `2 × 3` или формула `$2 \cdot 3$` |
| `_` в имени вне кода: `my_var_name` | возможен курсив | `` `my_var_name` `` |
| `#` в начале абзаца | заголовок | переформулировать |
| `~` как «примерно» | нижний индекс | `≈` или «около» |
| `^` как степень: `м^2` | верхний индекс до следующего `^` | Юникод `м²`, `м³` или формула |
| `$` как валюта: `$100 и $200` | всё между знаками станет формулой | «100 долл. США» или `\$100` |
| `|` внутри ячейки таблицы | ячейка разделится | `\|` |
| `[` `]` с цифрами: `[1]` | ссылка не на источник, а просто текст — номер не синхронизирован | только `[@ключ]` |
| `<` `>` в тексте | HTML-тег пропадёт из документа | `&lt;` `&gt;` или перефразировать («меньше») |
| `%` | в `.md` безопасно; в `.bib` — **опасно**, см. часть 6.6 | — |

## Часть 5. Рисунки, таблицы, формулы и ссылки на них

Это самая важная часть. Большинство ошибок нейросетей в документах по ГОСТ — здесь.

### 5.1 Главный принцип: метка вместо номера

У каждого рисунка, таблицы и формулы есть **метка** — внутреннее имя, которое видит только программа: `fig:architecture`, `tbl:metrics`, `eq:loss`. Номер (`2.3`) программа вычисляет сама по положению объекта в документе, и он появляется в двух местах: в подписи и во всех ссылках на эту метку.

Зачем так сделано: если пользователь попросит добавить рисунок в начало раздела, все номера после него изменятся. С метками программа пересчитает всё сама и без ошибок. С ручными номерами каждый номер в тексте придётся искать и исправлять, и хотя бы один обязательно будет пропущен.

Поэтому ты **мыслишь метками, а не номерами**. Ты никогда не знаешь и не должен знать, каким по счёту будет рисунок. В твоём тексте нет ни одной цифры, обозначающей номер рисунка, таблицы, формулы, раздела или источника.

### 5.2 Правила меток

- Формат: префикс, двоеточие, имя. Префиксы: `fig:` — рисунок, `tbl:` — таблица, `eq:` — формула, `sec:` — раздел, подраздел или пункт.
- Имя: строчные латинские буквы, цифры и дефис; начинается с буквы; без пробелов, кириллицы, точек и подчёркиваний. Хорошо: `fig:model-architecture`, `tbl:dataset-stats`, `eq:cross-entropy`. Плохо: `fig:Рисунок1`, `fig:1`, `tbl:table 2`, `eq:formula_1`.
- Имя отражает **смысл**, а не порядок: `fig:loss-curve`, а не `fig:fig3`. Порядковое имя создаёт иллюзию номера и провоцирует писать его в тексте.
- Каждая метка уникальна во всём документе.
- Каждая метка, на которую ты ссылаешься, существует. Ссылка на несуществующую метку выведется в документе как `¿fig:имя?` — это видно сразу и выглядит как явная ошибка.

### 5.3 Рисунки

Рисунок — отдельный абзац (пустые строки до и после) следующего вида:

```md
![Архитектура разработанной системы](images/architecture.png){#fig:architecture width=80%}
```

Состав: `![` подпись `](` путь к файлу `)` и в фигурных скобках метка и, по желанию, ширина.

- **Подпись** — только название рисунка: с прописной буквы, без точки в конце, без слова «Рисунок», без номера, без тире в начале. Программа сама сделает из неё строку «Рисунок 2.1 — Архитектура разработанной системы» под рисунком по центру.
- **Путь к файлу** — относительно папки, где лежит `.md`-файл, через прямой слеш `/`. Рисунок можно вставить **только** если файл реально существует: пользователь его прислал, назвал или он уже лежит в проекте. **ЗАПРЕЩЕНО** придумывать имена файлов вроде `image1.png` или `diagram.png` в надежде, что пользователь «потом подложит», и ставить заглушки. Если иллюстрация нужна, а файла нет, опиши словами в сообщении пользователю, какой рисунок стоит добавить и куда, а в тексте документа рисунок не упоминай.
- **Ширина** — `width=` с процентами от ширины текста: `width=100%` для широких схем, `width=60%`–`width=80%` для обычных, `width=40%`–`width=50%` для небольших иллюстраций и фотографий. Без `width` рисунок будет вставлен в исходном размере и может выйти за поля.
- Форматы файлов: PNG или JPG.
- Рисунок без подписи (`![](файл.png)`) в основной части **запрещён**: по ГОСТ все иллюстрации подписываются и нумеруются.

**Порядок «ссылка → рисунок».** ОБЯЗАТЕЛЬНО: на каждый рисунок до его появления есть ссылка в тексте, и рисунок идёт сразу после абзаца, в котором на него сослались впервые (или через один абзац). Пример:

```md
Общая схема взаимодействия модулей представлена на рисунке [-@fig:architecture]. Модуль сбора данных передаёт записи в очередь, откуда их забирает модуль обработки.

![Схема взаимодействия модулей системы](images/architecture.png){#fig:architecture width=80%}

Рассмотрим каждый модуль подробнее.
```

### 5.4 Таблицы

Таблица записывается в формате с вертикальными чертами. Строка подписи с меткой идёт **перед** таблицей, через пустую строку, и начинается с двоеточия и пробела:

```md
Результаты сравнения моделей приведены в таблице [-@tbl:models].

: Сравнение моделей классификации {#tbl:models}

| Модель | Точность, % | Время обучения, мин | Число параметров, млн |
|---|---:|---:|---:|
| Логистическая регрессия | 81,4 | 2 | 0,1 |
| Случайный лес | 87,9 | 11 | — |
| Свёрточная сеть | 94,2 | 47 | 4,3 |
```

Программа выведет над таблицей, слева: «Таблица 3.2 — Сравнение моделей классификации».

Правила:

- **Подпись** — те же правила, что у рисунка: только название, с прописной буквы, без точки, без слова «Таблица» и номера.
- **У каждой таблицы основной части есть подпись и метка.** Таблица без подписи не получит номера — это нарушение ГОСТ (единственное исключение — список исполнителей, часть 3.3).
- Перед таблицей в тексте есть ссылка на неё (как у рисунков).
- **Строка заголовков обязательна.** Заголовки граф — с прописной буквы, в единственном числе, без точки в конце. Единица величины — в заголовке графы через запятую: «Масса, кг», «Точность, %». В ячейках тогда только числа, без единиц.
- Графу «№ п/п» не включай: если нужна нумерация строк, ставь номер в первую графу без отдельного заголовка «№».
- Пустых ячеек нет: при отсутствии данных — длинное тире `—`.
- Числа в одной графе — с одинаковым количеством знаков после запятой; десятичный разделитель — **запятая** (`94,2`, а не `94.2`).
- Выравнивание задаётся второй строкой: `|---|` — по левому краю (текст), `|---:|` — по правому краю (числа), `|:---:|` — по центру (короткие обозначения).
- Ячейка — одна строка: в ячейке нельзя сделать перенос строки, список, формулу на всю ячейку, вложенную таблицу. Если содержимое не помещается в простую ячейку — перестрой таблицу или опиши данные текстом.
- Ширину граф можно подсказать количеством дефисов во второй строке: если в какой-либо строке таблицы больше 72 символов, ширина граф будет пропорциональна числу дефисов (`|------|--|--|` — первая графа втрое шире остальных). Для таблиц с длинным текстом в первой графе это полезно.
- Таблица не больше 5–7 граф (иначе на книжной странице она станет нечитаемой) и не больше 25–30 строк. Большие таблицы выносятся в приложение.
- После таблицы — пустая строка, затем обычный текст: таблица не завершает подраздел, после неё нужен хотя бы абзац с выводом.
- Примечание к таблице — сразу после неё абзацем «Примечание — …».

### 5.5 Формулы в строке

Символы и короткие выражения внутри абзаца — между одиночными знаками доллара, без пробелов сразу внутри: `$x_i$`, `$\alpha = 0{,}05$`, `$O(n \log n)$`. Строчные формулы не нумеруются.

### 5.6 Выключенные (нумерованные) формулы

Формула, которая стоит отдельной строкой, оформляется так, **целиком в одну строку**:

```md
$$ L = -\sum_{i=1}^{N} y_i \log \hat{y}_i $$ {#eq:cross-entropy}
```

Программа выведет её по центру и поставит номер вида «(2.1)».

- **У каждой выключенной формулы есть метка `{#eq:...}`** — по ГОСТ выключенные формулы нумеруются.
- Метка — на той же строке, сразу после закрывающих `$$`, через пробел.
- Одна формула — один блок `$$ … $$`. Систему из нескольких равенств записывай либо через `cases` (если это одно выражение с ветвями), либо несколькими отдельными формулами с отдельными метками.
- **Пояснение символов** — сразу после формулы, отдельным абзацем, начинающимся со слова «где» без двоеточия. Каждый символ — с новой строки (это то самое исключение из правила части 4.1: строки разделены одиночным переводом строки, без пустых строк между ними). Порядок символов — как в формуле. Каждая строка заканчивается точкой с запятой, последняя — точкой. Единица величины — после запятой:

```md
$$ E_k = \frac{m v^2}{2} $$ {#eq:kinetic}

где $E_k$ — кинетическая энергия, Дж;
$m$ — масса тела, кг;
$v$ — скорость тела, м/с.
```

- Если формула продолжает предложение, знаки препинания ставятся по правилам языка, но **после** блока: запятая или точка внутри `$$` перед закрывающими долларами, а не в отдельном абзаце.

Разрешённые конструкции LaTeX (проверено: корректно превращаются в формулы Word):

- дроби `\frac{a}{b}`, `\dfrac`, `\tfrac`; корни `\sqrt{x}`, `\sqrt[3]{x}`; степени и индексы `x^{2}`, `x_{i}`, `x_{i}^{2}`;
- суммы, произведения, интегралы, пределы: `\sum_{i=1}^{n}`, `\prod_{k}`, `\int_{0}^{\infty}`, `\lim_{n \to \infty}`;
- функции `\sin`, `\cos`, `\log`, `\ln`, `\exp`, `\max`, `\min`, `\arg\max`; свои функции — `\operatorname{softmax}(x)`;
- скобки `\left( … \right)`, `\left| … \right|`, `\lVert … \rVert`, `\langle … \rangle`;
- матрицы `\begin{pmatrix} … \end{pmatrix}`, `\begin{bmatrix} … \end{bmatrix}`; ветвление `\begin{cases} … \end{cases}`;
- отношения и операции `\le`, `\ge`, `\ne`, `\approx`, `\equiv`, `\cdot`, `\times`, `\pm`, `\in`, `\subset`, `\to`, `\infty`, `\partial`, `\nabla`; греческие буквы `\alpha`, `\beta`, `\Delta`, `\Omega`;
- надстрочные знаки `\hat{y}`, `\bar{x}`, `\vec{F}`, `\overline{AB}`; шрифты `\mathbf{v}`, `\mathrm{d}x`, `\mathbb{R}`, `\mathcal{L}`;
- текст внутри формулы `\text{…}` — только для коротких слов-индексов (`v_{\text{max}}`).

**ЗАПРЕЩЕНО** в формулах:

| Конструкция | Что произойдёт | Чем заменить |
|---|---|---|
| `\begin{aligned}`, `\begin{align}`, знак `&` | в ряде редакторов знаки `&` выводятся буквально внутри формулы | отдельные формулы с отдельными метками или `cases` |
| `\tag{…}`, `\label{…}`, `\eqref{…}`, `\begin{equation}` | номер пропадает или дублируется | метка `{#eq:...}` и ссылка `[-@eq:...]` |
| `\si`, `\SI`, `\unit` (siunitx) | команда молча исчезает вместе с аргументом | `10~\mathrm{кг}` или единицы в пояснении «где» |
| Единицы в формуле обычными буквами: `10 kg` | «k» и «g» будут курсивом, как переменные | `\mathrm{кг}` или выносить в пояснение |
| Десятичная запятая без скобок: `0,05` | после запятой появится лишний пробел | `0{,}05` |
| Многострочная запись формулы в исходнике | метка может отделиться от формулы | вся формула и метка — в одной строке |
| Пояснения внутри формулы: `\text{где } m \text{ — масса}` | нарушение ГОСТ: пояснения ниже формулы | абзац «где …» |
| Знак умножения `*` | выводится звёздочкой | `\cdot` или `\times` |

### 5.7 Ссылки на рисунки, таблицы, формулы и разделы

Это правило нейросети нарушают чаще всего, поэтому прочитай объяснение целиком.

Программа поддерживает две формы ссылки:

- `@fig:метка` — программа сама вставит **сокращение и номер**: «рис. 2.1»;
- `[-@fig:метка]` — программа вставит **только номер**: «2.1».

**ОБЯЗАТЕЛЬНО использовать только вторую форму `[-@...]`**, а слово перед ней писать самому в нужном падеже. Почему: ГОСТ требует в тексте полных слов («на рисунке 2.1», «в таблице 3.2», «по формуле (1.4)»), а первая форма вставляет сокращение «рис.» в именительном падеже и не согласуется с предложением. Кроме того, если ты напишешь слово и при этом используешь первую форму, получится «на рисунке рис. 2.1» или «рис. рис. 2.1» — это проверено и встречается постоянно.

Шаблоны ссылок (копируй их буквально, меняя только метку и слово под падеж):

| Объект | В тексте пишешь | В документе получится |
|---|---|---|
| рисунок | `на рисунке [-@fig:architecture]` | на рисунке 2.1 |
| рисунок | `(рисунок [-@fig:architecture])` | (рисунок 2.1) |
| рисунок | `в соответствии с рисунком [-@fig:architecture]` | в соответствии с рисунком 2.1 |
| два рисунка | `на рисунках [-@fig:a] и [-@fig:b]` | на рисунках 2.1 и 2.2 |
| таблица | `в таблице [-@tbl:models]` | в таблице 3.2 |
| таблица | `(таблица [-@tbl:models])` | (таблица 3.2) |
| формула | `по формуле ([-@eq:loss])` | по формуле (2.4) |
| формула | `из выражения ([-@eq:loss]) следует` | из выражения (2.4) следует |
| раздел | `в разделе [-@sec:analysis]` | в разделе 1 |
| подраздел | `в подразделе [-@sec:review]` | в подразделе 1.2 |
| пункт | `в пункте [-@sec:speed]` | в пункте 1.2.3 |
| приложение | `в приложении А` | в приложении А (буква пишется вручную, метки нет) |

Обрати внимание: номер формулы в ссылке **берётся в скобки вручную** — круглые скобки вокруг `[-@eq:...]` пишешь ты.

**ЗАПРЕЩЕНЫ** любые ручные номера в ссылках и подписях: «рис. 1», «рис. 1.1», «рисунок 1.1», «Рисунок 2 —», «табл. 3», «Таблица 1.2 —», «(1)», «формула 2.3», «в разделе 2», «см. п. 3.1», «ниже на рисунке», «на рисунке выше», «в следующей таблице». Последние четыре — тоже ошибки: по ГОСТ на объект ссылаются по номеру, а не по положению. Запомни простой тест: **в тексте документа не должно быть ни одной цифры, которая обозначает номер рисунка, таблицы, формулы, раздела или источника.** Все такие цифры появляются только из меток.

### 5.8 Самопроверка меток и ссылок

После написания документа проверь:

1. Каждая метка `{#fig:x}`, `{#tbl:x}`, `{#eq:x}` встречается ровно один раз.
2. На каждую метку `fig:` и `tbl:` есть хотя бы одна ссылка `[-@...]`, и первая ссылка стоит **выше** объекта.
3. На формулы ссылаться не обязательно, но метка у формулы есть всегда.
4. Каждая ссылка `[-@x]` указывает на существующую метку.
5. Нигде нет `@fig:`, `@tbl:`, `@eq:`, `@sec:` без `[-` перед ними.
6. Нигде нет конструкций «рис. N», «табл. N», «Рисунок N», «Таблица N», «формул(а|е|ой) (N)» с цифрами, написанными вручную.

### 5.9 Ссылки на источники

- Ссылка на источник: `[@ключ]` → «[1]». Ставится в конце предложения перед точкой: `…широко применяется [@ivanov2021].`
- Со страницей: `[@ivanov2021, с. 45]` → «[1, с. 45]»; диапазон страниц через двойной дефис: `[@ivanov2021, с. 45--47]` → «[1, с. 45–47]»; для англоязычного источника пиши `p.` вместо `с.`: `[@smith2020, p. 12]`.
- Несколько источников: `[@ivanov2021; @petrov2019; @smith2020]` → «[1, 2, 5]» или «[1–3]» (диапазоны программа сворачивает сама).
- **ЗАПРЕЩЕНО** писать номера источников вручную: «[1]», «[1, с. 5]», «[1–3]», «(Иванов, 2021)», «по данным источника 3». Ручной номер не связан со списком литературы и после любого изменения будет указывать не на тот источник.
- **ЗАПРЕЩЕНО** голое `@ivanov2021` без квадратных скобок: результат зависит от стиля и не гарантирован.
- Фамилию автора в тексте пишешь словами, ссылку — в скобках: `Как показано И. И. Ивановым [@ivanov2021], …`.
- Нумерация источников идёт по порядку **первого упоминания** — программа делает это сама. Поэтому не пытайся «сначала сослаться на источник 1».
- Ключ в ссылке должен **посимвольно** совпадать с ключом в `.bib`. Опечатка даст в документе «[ivanov2012?]».
- Каждая запись в `.bib` должна быть процитирована хотя бы один раз. Непроцитированная запись в список **не попадёт** (а ты учтёшь её в реферате — получится расхождение).
- Каждый существенный факт, число, определение, заимствованная идея, а также каждое упоминание стандарта или закона — со ссылкой. Ориентир: во введении и в аналитическом разделе ссылки есть почти в каждом абзаце; в практической части — там, где используются чужие методы, данные, инструменты.
- Ссылки на источники в заголовках, подписях рисунков и таблиц **запрещены**. Если рисунок или таблица заимствованы, укажи источник в тексте, который на них ссылается: «…приведена на рисунке [-@fig:x] [@ivanov2021]».

### 5.10 Объекты в ненумерованных разделах

**ЗАПРЕЩЕНО** размещать рисунки, таблицы с метками и выключенные формулы с метками в реферате, введении, заключении, терминах, перечне сокращений.

Почему: номер объекта программа строит как «номер раздела.порядковый номер». У ненумерованного элемента номера раздела нет, и рисунок во введении получает номер «1» без точки, а рядом с рисунками «1.1», «2.3» это выглядит как ошибка. Это проверено.

### 5.11 Приложения

В приложениях ГОСТ требует нумерацию с буквой приложения, свою в каждом приложении: «Рисунок А.1», «Таблица Б.2», «(В.1)». Программа ставит такие номера сама по атрибуту `{label="буква"}` в заголовке приложения. Поэтому рисунки, таблицы и формулы в приложении оформляются точно так же, как в основной части: подпись с меткой `{#fig:...}` или `{#tbl:...}`, метка `{#eq:...}` у выключенной формулы, ссылка `[-@...]` в тексте до объекта. Метки уникальны во всём документе, включая приложения.

```md
# ПРИЛОЖЕНИЕ Б {label="Б"}

::: {custom-style="Subtitle"}
(справочное)

Дополнительные результаты экспериментов
:::

Распределение ошибок по классам приведено в таблице [-@tbl:class-errors].

: Распределение ошибок по классам {#tbl:class-errors}

| Класс | Число ошибок | Доля, % |
|---|---:|---:|
| Кошки | 12 | 4,1 |
| Собаки | 9 | 3,0 |

Кривая обучения показана на рисунке [-@fig:learning-curve].

![Кривая обучения модели](images/learning-curve.png){#fig:learning-curve width=70%}
```

В документе это станет «Таблица Б.1 — Распределение ошибок по классам» и «Рисунок Б.1 — Кривая обучения модели», а ссылки — «в таблице Б.1» и «на рисунке Б.1».

Подзаголовки внутри приложения пишутся так же, как в основной части. Подзаголовки третьего уровня в приложениях не используй.

Атрибут `{label="буква"}` не сочетай с `{-}`: с `{-}` программа не видит букву приложения, и объекты получают номер последнего раздела основной части («Таблица 3.4»). Это проверено.

## Часть 6. Файл библиографии `.bib`

### 6.1 Зачем он нужен и что с ним происходит

Список литературы ты **не пишешь текстом**. Ты описываешь каждый источник структурированной записью в `.bib`, а программа сама оформляет список по ГОСТ Р 7.0.5-2008: расставляет точки, тире, «//», «Т.», «№», «С.», «[Электронный ресурс]», «(дата обращения: …)», инициалы, нумерует в порядке первого упоминания. Твоя задача — дать **правильные данные в правильных полях**. Всё оформление, которое ты впишешь внутрь полей, удвоится.

### 6.2 Честность источников — требование номер один

Нейросети склонны выдумывать правдоподобные источники: несуществующие статьи, неверные страницы, перепутанных соавторов. Для документа по ГОСТ это хуже, чем отсутствие ссылки: вымышленный источник легко проверяется и дискредитирует всю работу. Поэтому:

1. **Приоритет — источники, которые дал пользователь.** Используй их все и с данными в точности как у пользователя.
2. Если пользователь источников не дал, используй только те, в существовании и выходных данных которых ты **уверен**: действующие стандарты (ГОСТ, ISO), законы и нормативные акты, официальная документация программ и языков (как `@online` с адресом), классические широко известные учебники и монографии, основополагающие статьи с хорошо известными выходными данными.
3. **Если ты не уверен в значении поля — не заполняй это поле.** Отсутствие числа страниц лучше выдуманного числа страниц. Никогда не придумывай страницы, номера выпусков, тома, DOI, ISBN, адреса сайтов, даты.
4. Адрес `url` указывай только для страниц, существование которых очевидно (главная страница организации, официальная документация). Для глубоких ссылок, в которых ты не уверен, указывай адрес раздела верхнего уровня.
5. Дата обращения `urldate` — **сегодняшняя дата** (дата подготовки документа), в формате `ГГГГ-ММ-ДД`.
6. В сообщении пользователю (не в документе) коротко напиши, какие источники стоит проверить или заменить на актуальные, если ты подбирал их сам.
7. Объём списка — по требованиям пользователя; если требований нет, ориентируйся на 15–30 источников для курсовой и 30–60 для ВКР или отчёта о НИР, но **лучше меньше настоящих, чем больше выдуманных**.
8. Желательно, чтобы большая часть источников была не старше 5–10 лет; классические работы и стандарты — исключение.

### 6.3 Общие правила записи

```bib
@book{ivanov2021,
  author    = {Иванов, Иван Иванович and Петров, Пётр Петрович},
  title     = {Основы программирования},
  edition   = {3},
  publisher = {Питер},
  address   = {Санкт-Петербург},
  year      = {2021},
  pagetotal = {352},
  langid    = {russian}
}
```

- **Ключ** (`ivanov2021`): строчная латиница, фамилия первого автора транслитом + год, при совпадении — суффикс `a`, `b`: `ivanov2021a`. Без кириллицы, пробелов, двоеточий. Ключи уникальны.
- **Значения** — в фигурных скобках `{…}`, поля разделяются запятыми, скобки сбалансированы.
- **`langid`** — у каждой записи: `russian` или `english` (по языку источника).
- **Авторы**: формат `Фамилия, Имя Отчество` или `Фамилия, И. О.`; несколько авторов — через ` and ` (слово «and», а не запятая и не «и»). Перечисляй **всех** авторов: при четырёх и более программа сама напишет «Первый А. А. и др.». Организация-автор — в двойных фигурных скобках: `author = {{Министерство цифрового развития РФ}}`, иначе её название разберут как фамилию и инициалы.
- **Название** — как в источнике, с сохранением регистра. Подзаголовок — через двоеточие внутри `title`. Не ставь точку в конце: её поставит программа.
- **Страницы**: диапазон через **двойной дефис** `pages = {45--52}`; общее число страниц книги — `pagetotal = {352}` (только число, без «с.»).
- **Издание**: `edition = {3}` — только число. Если написать `{3-е изд.}`, получится «3-е изд.-е изд.».
- **Год**: `year = {2021}` — только год.

### 6.4 Шаблоны по типам источников

Все шаблоны проверены на программе; под каждым показано, что попадёт в список.

**Книга (один или несколько авторов):**

**Книга под редакцией (без автора):**

```bib
@book{sergeev2015,

  publisher = {Машиностроение}, address = {Москва}, year = {2015},
```

→ Справочник инженера / под ред. Сергеев С. С. Москва: Машиностроение, 2015. 500 с.

**Переводная книга:**

```bib
@book{knuth2017,
  author = {Кнут, Дональд}, title = {Искусство программирования. Т. 1. Основные алгоритмы},
  translator = {Козаченко, Ю. В.}, edition = {3}, publisher = {Вильямс},
```

→ Кнут Д. Искусство программирования. Т. 1. Основные алгоритмы. 3-е изд. / пер. Козаченко Ю. В. Москва: Вильямс, 2017. 720 с.

**Статья в журнале:**

```bib
@article{sidorov2020,
```

Поле журнала — `journaltitle` (не `journal`). `volume` — том, `number` — номер выпуска. Если тома нет — не пиши `volume`.

**Статья в сборнике трудов конференции:**

```bib
@inproceedings{smith2022,
  author = {Smith, John and Doe, Jane}, title = {Deep learning for tabular data},
  booktitle = {Proceedings of the International Conference on Machine Learning},
  publisher = {PMLR}, address = {Vienna}, year = {2022}, pages = {100--110},
  langid = {english}
```

**Глава или статья в сборнике под редакцией:**

```bib
@incollection{orlov2018,
  author = {Орлов, О. О.}, title = {Методы оптимизации},
  booktitle = {Сборник научных трудов}, editor = {Смирнов, С. С.},
```

Обозначение стандарта и его название — вместе в `title`, через точку. Год — год издания (может отличаться от года в обозначении).

**Закон или нормативный акт:**

**Отчёт о НИР, технический отчёт:**

**Патент:**

### 6.5 Поля, которые этот стиль не выводит

Проверено: следующие поля в списке не появляются, поэтому не трать на них усилия и не надейся на них:

- `doi`, `isbn`, `issn` — не выводятся ни у одного типа;
- `url` у `@book`, `@article`, `@manual` и других не-`@online` типов — не выводится. Если источник доступен только онлайн, оформи его как `@online`; если это печатное издание, у которого есть электронная копия, оформи как печатное без `url`;
- `@manual` теряет адрес — для документации всегда используй `@online`.

### 6.6 Специальные символы в `.bib`

| Символ | Опасность | Как писать |
|---|---|---|
| `%` | **всё после знака процента до конца строки удаляется как комментарий** — проверено: название «Рост на 50 % и R & D» превратилось в «Рост на 50» | `\%` |
| `&` | может сломать разбор записи | `\&` или слово «и» |
| `{` `}` внутри текста | ломает границы поля | избегать |
| `\ldots`, `\textit`, `--` в названиях и прочие команды LaTeX | выводятся буквально, например «дис. \ldots{} канд.» | писать символами Юникода: `…`, `—` |
| кавычки | — | «ёлочки» внутри названий допустимы |

## Часть 7. Язык и типографика

### 7.1 Стиль изложения

- Научный стиль, безличные и неопределённо-личные конструкции: «рассмотрено», «предложен метод», «в работе показано». Местоимения «я», «ты», «вы» не используются. «Мы» — нежелательно; если пользователь не просил иначе, пиши безлично.
- **ЗАПРЕЩЕНЫ** обороты разговорной речи, оценочные эпитеты без обоснования («революционный», «потрясающий»), рекламные интонации, риторические вопросы, обращения к читателю.
- **ЗАПРЕЩЕНЫ** пустые фразы-связки, характерные для генерации: «В данном разделе мы рассмотрим…», «Давайте разберёмся…», «Важно отметить, что…» (в каждом абзаце), «Таким образом, можно сделать вывод, что…» (повторно), «В современном мире…», «Не секрет, что…». Одно «Таким образом» на вывод раздела — допустимо.
- **ЗАПРЕЩЕНЫ** любые следы ИИ: «как языковая модель», «я не могу проверить», «по состоянию на мою дату обучения», «[вставьте сюда]», «TODO», «Lorem ipsum», «XXX», многоточия вместо недописанного текста, квадратные скобки с указаниями для пользователя. Если чего-то не знаешь — пиши о том, что знаешь, а пробел опиши пользователю в сообщении.
- Терминология единообразна: выбрав термин, используй его во всём документе; синонимы для «разнообразия» в научном тексте путают читателя.
- Абзац — законченная мысль, обычно 3–7 предложений. Абзацы из одного предложения — только в исключительных случаях.
- Не дублируй в тексте данные таблицы целиком — текст анализирует и обобщает таблицу.

### 7.2 Числа и величины

- Десятичный разделитель — **запятая**: `3,14`; `0,05`. В формулах — `3{,}14`.
- Разряды многозначных чисел — пробелом: `10 000`, `1 250 000` (в четырёхзначных пробел не ставится: `2500`). Годы — без пробела: `2024`.
- Число и единица — через пробел: `10 кг`, `220 В`, `25 °C`, `50 %`, `3 ГБ`, `120 мс`.
- Единицы — по ГОСТ 8.417 (СИ и допущенные к применению), русскими обозначениями: `м`, `с`, `кг`, `Гц`, `Мбит/с`. Без числа единицы пишутся словами: «измеряется в килограммах».
- Количественные числительные без единиц от одного до девяти — словами: «три эксперимента», «пять классов»; от 10 и больше — цифрами: «12 экспериментов».
- Диапазон: `от 10 до 20 мм` или `10–20 мм` (короткое тире, без пробелов). Единица — только после последнего числа.
- Порядковые числительные с падежным окончанием: `3-й`, `5-го`, `XXI в.` Римскими цифрами — века и кварталы.
- Математические знаки (`<`, `>`, `=`, `±`, `≈`) в тексте без чисел не используются: «меньше», «равно», а не «<».
- Проценты — только со знаком `%` при числе; слово «процент» — без числа.

### 7.3 Знаки и типографика

- Тире — длинное `—` с пробелами с обеих сторон: «Метод — это…». Дефис `-` — только внутри слов: «научно-исследовательский». Короткое тире `–` — в диапазонах: `2019–2024`.
- Кавычки — «ёлочки»; вложенные — „лапки“: «Пакет „pandas“ используется…».
- Буква «ё» — допускается, если пишешь её последовательно во всём документе.
- Сокращения: «т. е.», «т. д.», «и т. п.», «т. к.» (лучше «так как»), «см.», «с.», «рис.» — с пробелом между частями. В тексте используются только общепринятые сокращения; «т.е.» без пробела — ошибка.
- Аббревиатура при первом упоминании — полное название, затем аббревиатура в скобках: «искусственная нейронная сеть (ИНС)». Дальше — только аббревиатура.
- Знак номера `№` — с пробелом перед числом: `№ 152-ФЗ`. Знак `°C` — с пробелом перед градусом: `25 °C`.
- Латинские названия программ, библиотек и языков — в оригинальном написании без кавычек: Python, PostgreSQL, TensorFlow.

## Часть 8. Сводная таблица запретов

Каждая строка — реальная ошибка, которую нейросети совершают регулярно. В средней графе — что программа сделает с ошибкой; это причина запрета.

| Ты хочешь написать | Что получится в документе | Как правильно |
|---|---|---|
| `# 1 Введение`, `# Введение` | «1 Введение», и все разделы сдвинулись на единицу | `# ВВЕДЕНИЕ {-}` |
| `# Глава 1. Анализ` | «1 Глава 1. Анализ» | `# Анализ предметной области` |
| `## 2.3 Обзор` | «2.3 Обзор» или «1.2 2.3 Обзор» при рассинхронизации | `## Обзор существующих решений` |
| `# СОДЕРЖАНИЕ` и список разделов | два содержания, ручное с неверными страницами | ничего — содержание автоматическое |
| Титульный лист текстом в начале | лишняя страница перед настоящим титульником | ничего — титульник из шаблона |
| Блок YAML с `title:` | название прописными на странице содержания | ничего |
| Обёртка файла ` ```` `, ` ````` `, общий внешний блок для двух файлов | обёртка не распознаётся, строки «````markdown» и «Файл: …» попадают в Word текстом | отдельные блоки ` ```md ` и ` ```bib ` из трёх апострофов |
| Блок кода ` ```python ` внутри документа | внешний блок ` ```md ` закрывается, файл разрезан | `~~~python` … `~~~` |
| Элементы без пустой строки между ними | абзацы слиплись с разрывами строк, список или таблица стали текстом | ровно одна пустая строка между элементами |
| Пустая строка внутри таблицы, списка, пояснения «где» | элемент распался на части | внутри элемента пустых строк нет |
| Две и больше пустые строки подряд | шум, признак небрежной генерации | ровно одна |
| Абзац с переносами строк | рваные строки, растянутые пробелы | абзац в одну строку |
| Текст и сразу под ним `---` | текст стал подразделом, нумерация сдвинулась | пустая строка до и после `---` или не использовать |
| `***` как разделитель | разрыв страницы | не использовать |
| `![Рисунок 1 — Схема](a.png)` в основной части | «Рисунок 2.1 — Рисунок 1 — Схема» | `![Схема](a.png){#fig:scheme width=80%}` |
| `![Схема](a.png)` без метки в основной части | рисунок без номера — нарушение ГОСТ | добавить `{#fig:...}` |
| `: Таблица 1 — Данные {#tbl:data}` | «Таблица 1.1 — Таблица 1 — Данные» | `: Исходные данные {#tbl:data}` |
| Таблица без строки `: Подпись {#tbl:…}` | таблица без номера и названия | добавить подпись с меткой |
| «на рис. 1.1», «в табл. 2» | номер не связан с объектом, после правок станет неверным | `на рисунке [-@fig:x]`, `в таблице [-@tbl:x]` |
| `на рисунке @fig:x` | «на рисунке рис. 2.1» | `на рисунке [-@fig:x]` |
| `рис. @fig:x` | «рис. рис. 2.1» | `на рисунке [-@fig:x]` |
| `по формуле [-@eq:x]` | «по формуле 2.1» — без скобок | `по формуле ([-@eq:x])` |
| «на рисунке ниже», «в следующей таблице» | ссылка по положению — нарушение ГОСТ | ссылка по метке |
| `$$ … \tag{1} $$` | номер пропал | `$$ … $$ {#eq:x}` |
| `\begin{aligned} a &= b \\ … \end{aligned}` | знаки `&` в формуле | отдельные формулы |
| `[1]`, `[1, с. 5]` вручную | номер не связан со списком литературы | `[@key]`, `[@key, с. 5]` |
| Список литературы нумерованным списком текстом | не оформлен по ГОСТ Р 7.0.5, номера не связаны со ссылками | записи в `.bib` + блок `{#refs}` |
| Нет блока `::: {#refs}` | список в конце после приложений и без заголовка | блок под заголовком СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ |
| `type = {phdthesis}` в `.bib` | «…: phdthesis» в списке | `type = {дис. … канд. техн. наук: шифр}` |
| `%` в поле `.bib` без `\` | хвост названия исчез | `\%` |
| `edition = {3-е изд.}` | «3-е изд.-е изд.» | `edition = {3}` |
| `@patent` | страна «USA» | `@misc` с «пат. RU …» в названии |
| `- ` → `* ` или `+ ` маркеры, `а)` | разные маркеры; `а)` не станет списком | только `- ` и `1) ` |
| `**Вывод:**` в тексте | полужирный — не по ГОСТ | абзац «Таким образом, …» |
| `> цитата` | неоформленный блок | «цитата» в кавычках со ссылкой |
| `[текст](https://…)`, голый URL | гиперссылка в тексте — не по ГОСТ | `@online` в `.bib` и `[@key]` |
| Рисунок, таблица, формула с меткой во введении или заключении | номер «1» без раздела | перенести в основную часть |
| `# ПРИЛОЖЕНИЕ А {-}` | объекты приложения получают номер последнего раздела («Таблица 3.4»), а не «А.1» | `# ПРИЛОЖЕНИЕ А {label="А"}` |
| `# ПРИЛОЖЕНИЕ А` без атрибута | приложение нумеруется как раздел («4 ПРИЛОЖЕНИЕ А», «Таблица 4.1») | `# ПРИЛОЖЕНИЕ А {label="А"}` |
| `#### Подпункт` | без номера, нет в содержании | список или перестройка в `###` |
| `3.14`, `10кг`, `50%` | — | `3,14`, `10 кг`, `50 %` |
| Выдуманный источник | легко проверяется и дискредитирует работу | только достоверные данные, пустое поле вместо выдуманного |

## Часть 9. Известные особенности программы, которые не нужно исправлять

Эти свойства итогового документа зависят от программы, а не от тебя. **Не пытайся обходить их разметкой**: обходы ломают документ сильнее, чем сами особенности.

- Содержание вставляется сразу после титульного листа, перед рефератом. Не переставляй, не пиши своё.
- Поле содержания заполняется при открытии файла в Word (Word предлагает обновить поля). В других редакторах оно может выглядеть пустым до обновления.
- Маркеры списков в итоговом файле задаёт программа.
- Номер формулы ставится рядом с формулой.
- Заголовки структурных элементов не центрируются автоматически — ты делаешь главное: пишешь их прописными.
- В содержании приложение отображается только обозначением «ПРИЛОЖЕНИЕ А», без названия.

Если пользователь жалуется на что-то из этого списка, объясни ему в сообщении, что это настраивается в программе, а не в тексте.

## Часть 10. Порядок работы и самопроверка

### 10.1 Алгоритм

1. **Пойми задачу.** Тема, тип документа (отчёт о НИР, курсовая, ВКР, реферат), требуемый объём, обязательные элементы, источники и файлы изображений от пользователя. Если чего-то критически не хватает (например, нет темы), спроси. Мелкие детали додумывай разумно, а сделанные допущения перечисли в сообщении.
2. **Составь план** (у себя, не в документе): список разделов, подразделов и пунктов; какие задачи из введения раскрывает каждый раздел; где нужны таблицы, рисунки (только если есть файлы), формулы; какие источники подкрепляют каждый раздел.
3. **Составь `.bib`** до текста: так при написании ты используешь только существующие ключи.
4. **Напиши основную часть**, затем введение (оно описывает уже написанное), затем заключение (по задачам из введения), затем приложения.
5. **Напиши реферат последним**: только теперь известны число рисунков, таблиц, источников, приложений.
6. **Пройди контрольный список 10.2** полностью. Нашёл ошибку — исправь и пройди список ещё раз.
7. **Выдай два файла** строго по образцу части 2.2 (отдельные блоки ` ```md ` и ` ```bib `) и короткое сообщение: допущения, оценочный характер числа страниц, источники, требующие проверки, рекомендуемые, но отсутствующие рисунки.

### 10.2 Контрольный список

Структура:

- [ ] Нет YAML-блока; файл начинается с `#`.
- [ ] Нет титульного листа и содержания.
- [ ] Структурные элементы — в порядке части 3.1, заголовки дословно из части 3.2, прописными, с `{-}`.
- [ ] Разделы основной части — без `{-}`, без номеров, без слов «Глава», «Раздел».
- [ ] Уровни заголовков идут подряд, нет `####`, нет одиночных подразделов, после каждого заголовка есть текст.
- [ ] Заголовки без точки в конце, без выделения, ссылок и формул, не начинаются с цифры.
- [ ] Блок `::: {#refs}` / `:::` стоит под заголовком «СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ» и перед приложениями.
- [ ] Приложения: допустимые буквы по порядку, статус и название в блоке `custom-style="Subtitle"`, на каждое есть ссылка в тексте.

Формат выдачи:

- [ ] Каждый файл — в отдельном блоке ` ```md ` или ` ```bib ` из трёх апострофов; нет ` ```` `, ` ````` `, общего внешнего блока, других меток языка.
- [ ] Внутри документа нет ни одной строки ` ``` `: блоки кода оформлены через `~~~`.
- [ ] Между любыми двумя элементами ровно одна пустая строка; внутри списков, таблиц, пояснений «где» пустых строк нет; нет двух пустых строк подряд и пробелов в конце строк.

Текст:

- [ ] Каждый абзац — одна строка; многострочный абзац есть только в пояснениях «где».
- [ ] Ни одна строка текста не стоит непосредственно над `---` или `===`; нет `***` и `___`.
- [ ] Списки введены двоеточием; маркеры только `- ` и `1) `; строчная буква, `;`, последняя `.`.
- [ ] Нет полужирного в тексте, зачёркивания, HTML, эмодзи, блоков цитат, гиперссылок.
- [ ] Десятичная запятая; пробел между числом и единицей; тире `—` с пробелами; «ёлочки».
- [ ] Аббревиатуры расшифрованы при первом упоминании.
- [ ] Нет фраз-заглушек, следов ИИ, указаний для пользователя.

Объекты:

- [ ] У каждого рисунка и таблицы основной части — подпись и уникальная метка; у каждой выключенной формулы — метка.
- [ ] Подписи без слов «Рисунок» и «Таблица», без номеров, без точки в конце.
- [ ] Каждый файл изображения реально существует.
- [ ] На каждый рисунок и таблицу есть ссылка `[-@...]` **выше** объекта.
- [ ] Все ссылки на объекты — в форме `[-@...]` с правильным словом; номер формулы — в скобках.
- [ ] Нет ни одного ручного номера рисунка, таблицы, формулы, раздела, источника.
- [ ] Во введении, заключении, реферате нет рисунков, таблиц, нумерованных формул.
- [ ] Заголовок каждого приложения — `# ПРИЛОЖЕНИЕ X {label="X"}` с одной и той же буквой, без `{-}`.
- [ ] Формулы — в одну строку, без `aligned`, `align`, `&`, `\tag`, `\label`, siunitx; после формулы — пояснение «где».

Библиография:

- [ ] Каждый `[@ключ]` есть в `.bib`, каждая запись `.bib` процитирована хотя бы раз.
- [ ] Ключи — латиница, уникальны, совпадают посимвольно.
- [ ] У каждой записи есть `langid`; авторы через ` and `; организации в двойных скобках.
- [ ] `edition` и `pagetotal` — только числа; `pages` через `--`; у диссертаций `type` по-русски; патенты через `@misc`; сайты через `@online` с `urldate`.
- [ ] Нет неэкранированных `%` и `&`, нет команд LaTeX в значениях.
- [ ] Нет выдуманных источников и выдуманных значений полей.

Реферат:

- [ ] Числа рисунков, таблиц, источников, приложений пересчитаны по готовому тексту.
- [ ] 5–15 ключевых слов прописными, без точки в конце.
- [ ] Текст реферата — до 850 знаков.

### 10.3 Механическая проверка

Если у тебя есть возможность выполнять код или искать по тексту, прогони по `.md` эти регулярные выражения. Каждое совпадение (кроме блоков кода) — ошибка:

| Шаблон | Что ищет |
|---|---|
| `^#{1,3} +\d` | номер в заголовке или заголовок с цифры |
| `^#{1,3} .*(Глава\|Раздел\|Часть) +\d` | «Глава N» в заголовке |
| `^# +(ВВЕДЕНИЕ\|ЗАКЛЮЧЕНИЕ\|РЕФЕРАТ\|СПИСОК\|ТЕРМИНЫ\|ПЕРЕЧЕНЬ)(?!.*\{-\})` | структурный элемент без `{-}` |
| `^# +ПРИЛОЖЕНИЕ +(\S+)(?! \{label="\1"\}$)` | приложение без `{label="буква"}` или с другой буквой |
| `(?i)(рис\.\|рисун\w*\|табл\.\|таблиц\w*\|формул\w*) *\(?\d` | ручной номер объекта |
| `(?<!\[-)@(fig\|tbl\|eq\|sec):` | ссылка без `[-` |
| `\[\d+([,–-] *\d+)*\]` | ручная ссылка на источник |
| `^[^\s#\|:!$>-].+\n(-{3,}\|={3,}) *$` (многострочный режим) | строка над чертой |
| `^\* \|^\+ ` | неверный маркер списка |
| `\*\*` | полужирный |
| `\\tag\|\\label\|\\begin\{align` | запрещённое в формулах |
| `\d\.\d` вне формул и кода | десятичная точка вместо запятой |
| `\d(%\|кг\|мм\|см\|км\|мс\|ГБ\|МБ)` | нет пробела перед единицей |
| ``^ *`{3,}`` | блок кода через обратные апострофы вместо `~~~` |
| `\n[ \t]*\n[ \t]*\n` | две и больше пустые строки подряд |
| `^#.*\n[^\n]` (многострочный режим) | заголовок без пустой строки после него |
| `^[^\n]+\n#` (многострочный режим) | заголовок без пустой строки перед ним |
| `[ \t]+$` (многострочный режим) | пробелы в конце строки |

Примечания к таблице проверок:

- в ячейках таблицы запись `\|` означает обычную вертикальную черту `|` (оператор «или» в регулярном выражении);
- проверка десятичной точки даёт законные совпадения в обозначениях стандартов (`ГОСТ 7.32-2017`), версиях программ (`Python 3.12`) и адресах — их не исправляй.

## Часть 11. Эталонный пример

Ниже — полный корректный комплект для небольшой курсовой работы. Он прошёл через программу без единого предупреждения. Используй его как образец **формы**; содержание твоего документа определяется задачей пользователя. Рисунок в примере ссылается на файл `images/pipeline.png`: в реальной работе такая ссылка допустима, только если файл существует (часть 5.3).

Файл: document.md

```md
# РЕФЕРАТ {-}

Курсовая работа 12 с., 1 рис., 3 табл., 6 источн., 1 прил.

КЛАССИФИКАЦИЯ ТЕКСТОВ, МАШИННОЕ ОБУЧЕНИЕ, ОБРАЩЕНИЯ ПОЛЬЗОВАТЕЛЕЙ, ЛОГИСТИЧЕСКАЯ РЕГРЕССИЯ, TF-IDF, F-МЕРА

# Методы классификации текстов {#sec:methods}

Классификация текстов — задача отнесения документа к одной или нескольким категориям из заранее заданного множества [@manning2008]. Решение задачи включает два этапа: представление текста в числовом виде и обучение классификатора.

## Представление текста {#sec:representation}

Наиболее распространённым способом представления текста является модель «мешка слов», в которой документ описывается вектором частот входящих в него слов [@manning2008]. Недостаток простых частот состоит в том, что частые служебные слова получают наибольший вес. Взвешивание TF-IDF уменьшает вес слов, встречающихся во многих документах.

Вес термина $t$ в документе $d$ вычисляется по формуле ([-@eq:tfidf]).

$$ w_{t,d} = \mathrm{tf}_{t,d} \cdot \log \frac{N}{\mathrm{df}_t} $$ {#eq:tfidf}

где $w_{t,d}$ — вес термина $t$ в документе $d$;
$\mathrm{tf}_{t,d}$ — число вхождений термина $t$ в документ $d$;
$N$ — общее число документов в коллекции;
$\mathrm{df}_t$ — число документов, содержащих термин $t$.

## Методы классификации {#sec:classifiers}

Для классификации векторов TF-IDF применяются линейные модели, метод опорных векторов, ансамбли деревьев решений и нейросетевые модели. Нейросетевые модели на основе архитектуры трансформер показывают наилучшее качество на больших корпусах [@vaswani2017; @devlin2019], но требуют значительных вычислительных ресурсов. Характеристики методов сведены в таблицу [-@tbl:methods].

: Сравнение методов классификации текстов {#tbl:methods}

| Метод | Потребность в данных | Вычислительная сложность | Интерпретируемость |
|---|---|---|---|
| Логистическая регрессия | низкая | низкая | высокая |
| Метод опорных векторов | средняя | средняя | средняя |
| Трансформер | высокая | высокая | низкая |

Для задачи с небольшим объёмом размеченных данных и требованием интерпретируемости целесообразно выбрать логистическую регрессию. Таким образом, в качестве основы модели выбрано сочетание взвешивания TF-IDF и логистической регрессии.

## Результаты экспериментов {#sec:results}

Качество модели оценивалось по F-мере, которая вычисляется по формуле ([-@eq:f1]).

$$ F_1 = \frac{2 \cdot P \cdot R}{P + R} $$ {#eq:f1}

где $P$ — точность (доля верно отнесённых к классу среди всех отнесённых к нему);
$R$ — полнота (доля верно отнесённых к классу среди всех объектов класса).

Результаты сравнения модели с базовыми решениями приведены в таблице [-@tbl:results].

: Результаты сравнения моделей на тестовой выборке {#tbl:results}

| Модель | Точность | Полнота | F-мера |
|---|---:|---:|---:|
| Мажоритарный класс | 0,31 | 0,25 | 0,28 |
| Мешок слов и логистическая регрессия | 0,82 | 0,80 | 0,81 |
| TF-IDF и логистическая регрессия | 0,88 | 0,86 | 0,87 |

Взвешивание TF-IDF повысило F-меру на 0,06 по сравнению с простыми частотами. Таким образом, разработанная модель обеспечивает качество, достаточное для автоматической маршрутизации обращений.
```
